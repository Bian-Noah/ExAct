一个简单且可扩展的代码库，用于训练和微调用于通用机器人操作的视觉-语言-动作模型（VLA）：

- **不同的数据集混合：我们原生支持 RLDS 格式的任意数据集，包括来自**[Open X-Embodiment 数据集](https://robotics-transformer-x.github.io/)的任意混合数据。
- **易于扩展**：借助 PyTorch FSDP 和 Flash-Attention，我们可以快速高效地训练 10 亿至 340 亿参数的模型，并轻松适应不同的模型架构。
- **原生微调支持**：内置支持（附带示例）各种形式的微调（完全微调、部分微调、LoRA）。

基于[棱镜式VLM](https://github.com/TRI-ML/prismatic-vlms)构建。

## 入门

为了方便用户开始加载和运行 OpenVLA 模型进行推理，我们提供了一个轻量级的接口，该接口利用了 HuggingFace `transformers`AutoClasses，并且依赖项极少。

例如，要在[BridgeData V2 环境](https://rail-berkeley.github.io/bridgedata/)中使用 WidowX 机器人`openvla-7b`进行零次指令跟踪
加载：[link](https://rail-berkeley.github.io/bridgedata/)

```
# Install minimal dependencies (`torch`, `transformers`, `timm`, `tokenizers`, ...)
# > pip install -r https://raw.githubusercontent.com/openvla/openvla/main/requirements-min.txt
from transformers import AutoModelForVision2Seq, AutoProcessor
from PIL import Image

import torch

# Load Processor & VLA
processor = AutoProcessor.from_pretrained("openvla/openvla-7b", trust_remote_code=True)
vla = AutoModelForVision2Seq.from_pretrained(
    "openvla/openvla-7b", 
    attn_implementation="flash_attention_2",  # [Optional] Requires `flash_attn`
    torch_dtype=torch.bfloat16, 
    low_cpu_mem_usage=True, 
    trust_remote_code=True
).to("cuda:0")

# Grab image input & format prompt
image: Image.Image = get_from_camera(...)
prompt = "In: What action should the robot take to {<INSTRUCTION>}?\nOut:"

# Predict Action (7-DoF; un-normalize for BridgeData V2)
inputs = processor(prompt, image).to("cuda:0", dtype=torch.bfloat16)
action = vla.predict_action(**inputs, unnorm_key="bridge_orig", do_sample=False)

# Execute...
robot.act(action, ...)
```

我们还提供了一个[示例脚本，用于针对新任务和实现微调 OpenVLA 模型](https://github.com/openvla/openvla/blob/main/vla-scripts/finetune.py)；该脚本支持不同的微调模式，包括[HuggingFace 的 PEFT 库](https://huggingface.co/docs/peft/en/index)支持的（量化）低秩自适应 (LoRA) 。

对于部署，我们提供了一个轻量级脚本，[用于通过 REST API 提供 OpenVLA 模型](https://github.com/openvla/openvla/blob/main/vla-scripts/deploy.py)，从而提供了一种将 OpenVLA 模型集成到现有机器人控制堆栈中的简便方法，无需强大的设备端计算能力。

## 预训练的VLA

我们发布了两个在我们工作中训练的 OpenVLA 模型，检查点、配置和模型卡可[在我们的 HuggingFace 页面上](https://huggingface.co/openvla)找到：

- [openvla-7b](https://huggingface.co/openvla/openvla-7b)：我们论文中的旗舰模型，基于棱镜视觉模型`prism-dinosiglip-224px`（Prismatic VLM，融合了DINOv2和SigLIP视觉骨干网以及Llama-2 LLM）训练而成。该模型在Open X-Embodiment的大型混合数据集上进行训练，涵盖97万条轨迹（[混合数据集详情请参见“Open-X Magic Soup++”](https://github.com/openvla/openvla/blob/main/prismatic/vla/datasets/rlds/oxe/mixtures.py)）。
- [openvla-v01-7b](https://huggingface.co/openvla/openvla-7b-v01)：这是开发过程中使用的早期模型，基于 Prismatic `siglip-224px`VLM（单一 SigLIP 视觉骨干网和 Vicuña v1.5 LLM）进行训练。它使用与[Octo](https://github.com/octo-models/octo)相同的混合数据集进行训练，但 GPU 运行时间比我们的最终模型要少得多（[混合数据集详情 - 请参阅“Open-X Magic Soup”](https://github.com/openvla/openvla/blob/main/prismatic/vla/datasets/rlds/oxe/mixtures.py)）。

**关于模型许可和商业用途的明确说明**：虽然本仓库中的所有代码均以 MIT 许可证发布，但我们的预训练模型可能继承了我们所用底层基础模型的限制。具体而言，上述两个模型均源自 Llama-2，因此受
[Llama 社区许可证的](https://ai.meta.com/llama/license/)约束。

## 安装

> **注意**：这些安装说明适用于完整规模的预训练（和分布式微调）；如果只想使用 OpenVLA 模型运行推理（或执行轻量级微调），请参阅上面的说明！

本仓库使用 Python 3.10 构建，但应向下兼容 Python 3.8 及更高版本。我们需要 PyTorch 2.2.* 版本——安装说明[请参见此处](https://pytorch.org/get-started/locally/)。本仓库的最新版本已使用以下环境开发并经过全面测试：

- PyTorch 2.2.0、torchvision 0.17.0、transformers 4.40.1、tokenizers 0.19.1、timm 0.9.10 和 flash-attn 2.5.5

**[2024年5月21日] 注意**：鉴于后续版本中已报告的回归问题和重大变更`transformers`，`timm`我们
`tokenizers`明确限制了上述依赖项的版本。我们正在努力实现全面的测试，并计划尽快放宽这些限制。

使用以下设置命令开始操作：

```
# Create and activate conda environment
conda create -n openvla python=3.10 -y
conda activate openvla

# Install PyTorch. Below is a sample command to do this, but you should check the following link
# to find installation instructions that are specific to your compute platform:
# https://pytorch.org/get-started/locally/
conda install pytorch torchvision torchaudio pytorch-cuda=12.4 -c pytorch -c nvidia -y  # UPDATE ME!

# Clone and install the openvla repo
git clone https://github.com/openvla/openvla.git
cd openvla
pip install -e .

# Install Flash Attention 2 for training (https://github.com/Dao-AILab/flash-attention)
#   =>> If you run into difficulty, try `pip cache remove flash_attn` first
pip install packaging ninja
ninja --version; echo $?  # Verify Ninja --> should return exit code "0"
pip install "flash-attn==2.5.5" --no-build-isolation
```

如果在安装过程中遇到任何问题，请提交 GitHub Issue。

**注意：**请参阅[此处](链接)`vla-scripts/`以获取完整的 OpenVLA 模型训练和验证脚本。请注意，此仓库`scripts/`主要保留了原始（基础）`prismatic-vlms`仓库的内容，支持训练和评估视觉条件语言模型；虽然您可以使用此仓库训练 VLM 和 VLA，但请注意，尝试使用`scripts/generate.py`现有的 OpenVLA 模型生成语言（通过[此处](链接)）将无法正常工作（因为我们仅训练当前的 OpenVLA 模型来生成动作，且仅用于生成动作）。

## 通过 LoRA 对 OpenVLA 进行微调

**（2025年3月3日更新：我们建议尝试新的 OFT 方案来微调 OpenVLA，以生成更快、更成功的策略。请访问项目网站[。](https://openvla-oft.github.io/)）**

本节讨论如何使用 Hugging Face`transformers`库通过低秩自适应 (LoRA) 对 OpenVLA 进行微调。如果您没有足够的计算资源来完全微调一个 70 亿参数的模型，建议使用此方法。LoRA 微调的主脚本是 [此处应填写脚本地址] `vla-scripts/finetune.py`。（如果您希望进行完全微调，请参阅
“完全微调 OpenVLA”部分。）

下面我们展示如何通过 LoRa 对 OpenVLA 主检查点进行微调。这里我们使用配备 80 GB 显存的单个 A100 GPU 在[BridgeData V2](https://rail-berkeley.github.io/bridgedata/)[openvla-7b](https://huggingface.co/openvla/openvla-7b)上进行微调。（您也可以使用显存较小的 GPU 进行微调，只要其显存至少约为 27 GB，方法是修改批处理大小。）[link](https://rail-berkeley.github.io/bridgedata/)

首先，下载 BridgeData V2 数据集：

```
# Change directory to your base datasets folder
cd <PATH TO BASE DATASETS DIR>

# Download the full dataset (124 GB)
wget -r -nH --cut-dirs=4 --reject="index.html*" https://rail.eecs.berkeley.edu/datasets/bridge_release/data/tfds/bridge_dataset/

# Rename the dataset to `bridge_orig` (NOTE: Omitting this step may lead to runtime errors later)
mv bridge_dataset bridge_orig
```

现在，运行如下所示的 LoRA 微调脚本。请注意，该脚本`--batch_size==16`需要`--grad_accumulation_steps==1`
约 72 GB 的 GPU 内存。如果您的 GPU 内存较小，则应减少 ` --batch-size` 参数`--batch_size`并增加`--grad_accumulation_steps`
`--batch-size` 参数，以保持足够大的有效批处理大小，从而实现稳定的训练。如果您有多个 GPU 并希望通过 PyTorch 分布式数据并行 (DDP) 进行训练，只需`--nproc-per-node`在`torchrun`以下命令中将 `--batch-size` 设置为可用 GPU 的数量即可。

```
torchrun --standalone --nnodes 1 --nproc-per-node 1 vla-scripts/finetune.py \
  --vla_path "openvla/openvla-7b" \
  --data_root_dir <PATH TO BASE DATASETS DIR> \
  --dataset_name bridge_orig \
  --run_root_dir <PATH TO LOG/CHECKPOINT DIR> \
  --adapter_tmp_dir <PATH TO TEMPORARY DIR TO SAVE ADAPTER WEIGHTS> \
  --lora_rank 32 \
  --batch_size 16 \
  --grad_accumulation_steps 1 \
  --learning_rate 5e-4 \
  --image_aug <True or False> \
  --wandb_project <PROJECT> \
  --wandb_entity <ENTITY> \
  --save_steps <NUMBER OF GRADIENT STEPS PER CHECKPOINT SAVE>
```

`--image_aug==False`注意：如果在上面的命令中进行设置，您将`action_accuracy`在训练日志中看到接近 100% 的结果，因为该[openvla-7b](https://huggingface.co/openvla/openvla-7b)模型已经在包含 BridgeData V2 的数据集的超集上进行了预训练（没有进行数据增强）。

要使用不同的数据集进行 LoRa 微调，您可以从[Open X-Embodiment (OXE)](https://robotics-transformer-x.github.io/)
混合模型下载数据集（有关如何从 OXE 下载数据集的示例，请参阅[此自定义脚本](https://github.com/moojink/rlds_dataset_mod/blob/main/prepare_open_x.sh)）。或者，如果您有不属于 OXE 的自定义数据集，您可以选择 (a) 将数据集转换为与我们的微调脚本兼容的 RLDS 格式（有关说明，请参阅[此仓库](https://github.com/kpertsch/rlds_dataset_builder)），或者 (b) 使用您自己的自定义 PyTorch 数据集包装器（有关说明，请参阅`vla-scripts/finetune.py`注释）。我们建议大多数用户选择选项 (a)；RLDS 数据集和数据加载器经过更广泛的测试，因为我们所有的预训练和微调实验都使用了它们。

对于选项 (a)，在将数据集转换为 RLDS 后，您需要将其注册到我们的数据加载器中，方法是在[此处注册数据集配置，在](https://github.com/openvla/openvla/blob/main/prismatic/vla/datasets/rlds/oxe/configs.py#L54)[此处](https://github.com/openvla/openvla/blob/main/prismatic/vla/datasets/rlds/oxe/transforms.py#L828)注册数据集转换函数。

集成新数据集后，您可以使用上述脚本启动 LoRa 微调`vla-scripts/finetune.py`。如果遇到任何问题，请访问VLA 故障排除部分或在[OpenVLA GitHub Issues 页面](https://github.com/openvla/openvla/issues?q=)（包括已关闭的问题）中搜索类似问题
。如果找不到类似问题，请随时创建新问题。

## 完全微调 OpenVLA

**（2025年3月3日更新：我们建议尝试新的 OFT 方案来微调 OpenVLA，以生成更快、更成功的策略。请访问项目网站[。](https://openvla-oft.github.io/)）**

在本节中，我们将讨论完全微调[使用Prismatic VLMs](https://github.com/TRI-ML/prismatic-vlms)训练脚本，通过原生 PyTorch 全分片数据并行 (FSDP) 对 OpenVLA（全部 75 亿个参数）进行微调。完整的微调过程更为复杂，仅建议在您拥有足够的计算资源（例如，一个包含 8 个 A100 GPU 的完整节点）且 LoRA 微调不足以满足您的应用场景（例如，微调分布与预训练分布差异显著）的情况下进行。否则，我们建议您尝试使用 LoRA 进行参数高效的微调，具体方法请参阅“
使用 LoRA 微调 OpenVLA”部分。

### 将棱镜模型转换为贴合面

如果您使用 Prismatic VLMs 代码库训练模型（例如，如果您在新数据集上对 OpenVLA 进行了完整的微调），则需要将最终检查点转换为与 Hugging Face
 `transformers`AutoClasses 兼容的版本。本节将讨论如何进行转换。

Let's say your training run directory is `PRISMATIC_RUN_DIR` (e.g., `prism-dinosiglip-224px+mx-oxe-magic-soup-plus+n8+b32+x7`).
Inside this directory, there should be a directory called `checkpoints` which contains saved model checkpoints (e.g.,
`step-295000-epoch-40-loss=0.2200.pt`). The Prismatic-to-Hugging-Face conversion script
([convert_openvla_weights_to_hf.py](https://github.com/openvla/openvla/blob/main/vla-scripts/extern/convert_openvla_weights_to_hf.py)) expects a checkpoint file
named `latest-checkpoint.pt`. Therefore, you should first create a symbolic link called `latest-checkpoint.pt` that
points to the checkpoint file that you wish to convert:

```
# Go to your Prismatic training run's `checkpoints` directory
cd PRISMATIC_RUN_DIR/checkpoints

# Create symbolic link pointing to your checkpoint file
ln -s <YOUR CHECKPOINT FILENAME> latest-checkpoint.pt
```

Then, launch the conversion script to convert the checkpoint from the Prismatic VLMs format to the Hugging Face format:

```
python vla-scripts/extern/convert_openvla_weights_to_hf.py \
    --openvla_model_path_or_id <PRISMATIC_RUN_DIR> \
    --output_hf_model_local_path <OUTPUT DIR FOR CONVERTED CHECKPOINT>
```

The command above will save the HF-compatible checkpoint in `output_hf_model_local_path`. Now you can load the checkpoint
with HF AutoClasses as normal, as shown below. Note that there is an additional necessary step to register the OpenVLA model
to HF AutoClasses before loading it because you are loading a locally saved checkpoint rather than one that is pushed to the
HF Hub (see [here](https://huggingface.co/docs/transformers/en/custom_models#registering-a-model-with-custom-code-to-the-auto-classes)
for details).

```
import torch
from transformers import AutoConfig, AutoImageProcessor, AutoModelForVision2Seq, AutoProcessor

from prismatic.extern.hf.configuration_prismatic import OpenVLAConfig
from prismatic.extern.hf.modeling_prismatic import OpenVLAForActionPrediction
from prismatic.extern.hf.processing_prismatic import PrismaticImageProcessor, PrismaticProcessor

# Register OpenVLA model to HF AutoClasses (not needed if you pushed model to HF Hub)
AutoConfig.register("openvla", OpenVLAConfig)
AutoImageProcessor.register(OpenVLAConfig, PrismaticImageProcessor)
AutoProcessor.register(OpenVLAConfig, PrismaticProcessor)
AutoModelForVision2Seq.register(OpenVLAConfig, OpenVLAForActionPrediction)

# Load Processor & VLA
processor = AutoProcessor.from_pretrained("<PATH TO CONVERTED CHECKPOINT DIR>", trust_remote_code=True)
vla = AutoModelForVision2Seq.from_pretrained(
    "<PATH TO CONVERTED CHECKPOINT DIR>",
    attn_implementation="flash_attention_2",  # [Optional] Requires `flash_attn`
    torch_dtype=torch.bfloat16,
    low_cpu_mem_usage=True,
    trust_remote_code=True,
).to("cuda:0")

...
```
## Training VLAs from Scratch

We provide full instructions and configurations for training VLA models on (arbitrary subsets of) the
[Open X-Embodiment (OXE) Dataset](https://robotics-transformer-x.github.io/). If you run in to any issues with

### VLA Pretraining Datasets

We download and preprocess individual datasets from Open X-Embodiment in [RLDS format](https://github.com/google-research/rlds) following
[this custom script](https://github.com/moojink/rlds_dataset_mod/blob/main/prepare_open_x.sh). See
[mixtures.py](https://github.com/openvla/openvla/blob/main/prismatic/vla/datasets/rlds/oxe/mixtures.py) for the full list of component datasets (and mixture
weights) we use to train `openvla-7b`.

- **Important**: For the BridgeData V2 component, the version in OXE is out of date (as of 12/20/2023). Instead,
you should download the dataset from the [official website](https://rail.eecs.berkeley.edu/datasets/bridge_release/data/tfds/bridge_dataset/) and place it under the subdirectory `bridge_orig/`.
Replace any reference to `bridge` in the OXE code with `bridge_orig`.

### VLA Configuration & Training Script

The entry point for VLA training is [vla-scripts/train.py](https://github.com/openvla/openvla/blob/main/vla-scripts/train.py). We use
[draccus](https://pypi.org/project/draccus) to provide a modular, dataclass-based interface for specifying VLA
training configurations; existing VLA configurations are in [prismatic/conf/vla.py](https://github.com/openvla/openvla/blob/main/prismatic/conf/vla.py). You can
add your own training configuration and refer to it using the `--vla.type` command line argument.

We use PyTorch Fully Sharded Data Parallel (FSDP) to distribute training across GPUs. Launch training via `torchrun`:

```

torchrun --standalone --nnodes 1 --nproc-per-node 8 vla-scripts/train.py \
  --vla.type "prism-dinosiglip-224px+mx-bridge" \
  --data_root_dir <PATH TO OXE DATA ROOT> \
  --run_root_dir <PATH TO LOG/CHECKPOINT ROOT> \
  --wandb_project "<PROJECT>" \
  --wandb_entity "<ENTITY>"
```

# VLA Performance Troubleshooting

In this section we cover best practices for debugging poor VLA performance after fine-tuning on your target domain robot dataset.

**Note**: OpenVLA typically requires fine-tuning on a small demonstration dataset (~100 demos) from your target domain robot. Out-of-the-box, it only works well on domains from the training dataset.

**Sanity checks**:

- replay the actions from a demonstration from your fine-tuning dataset and make sure that the robot can execute the task successfully (this ensures that your data collection pipeline is correct)
- once you fine-tuned a model, load the model in your inference pipeline (as if you would run it to control the robot), but feed images from the fine-tuning dataset into the model (pretending they come from the robot) and verify that you can reproduce the token accuracies / L1 errors from training (this ensures that your inference pipeline is correct)

**优化数据收集的最佳实践**：如果您的设置通过了以上两项健全性检查，那么问题可能不在于模型训练，而在于您用于优化模型的数据。以下是一些数据收集的最佳实践：

- *以 5-10Hz 左右的控制频率采集数据。OpenVLA*模型未经动作分块训练，经验表明该模型难以处理高频数据。如果您的机器人设置使用高频控制器（例如 50Hz），请考虑将动作采样率降至 5Hz。首先验证您的机器人在使用 5Hz 动作时是否仍能完成任务（即，使用 5Hz 动作重复上述验证步骤 (1)）。
- *避免在数据采集过程中出现停顿或小动作。*由于 OpenVLA 的训练过程中未进行动作分块，模型对微调数据中的空闲动作较为敏感。如果您的数据中包含机器人几乎静止不动的步骤，模型在推理时可能会“卡住”在这些步骤中。请尽量采集机器人持续缓慢移动的微调演示数据。
- *确保数据覆盖范围足够。*如果您计划对模型进行一些变化测试，例如改变物体的初始位置，请确保您的微调数据也包含足够多样化的此类条件，例如展示具有不同初始条件的演示数据。
- *在数据收集过程中使用一致的任务策略。*这并非硬性规定，但可以简化你的工作。尽量以一致的方式演示任务，例如从同一侧接近物体，即使子步骤可以以任意顺序执行，也应按相同的顺序执行。保持一致性可以减少用于微调的数据集的多模态性，从而简化建模问题。
